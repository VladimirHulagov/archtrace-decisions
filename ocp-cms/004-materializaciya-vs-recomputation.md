# Materialization vs recomputation: формализованные trade-offs и динамическая настройка

## Context and Problem Statement

Для KV cache и агентных нагрузок выбор «материализовать состояние или пересчитывать» сегодня делает разработчик приложения фиксированно. Итог дискуссии: нагрузкам нужна формализованная характеристика этих trade-off и динамическая настройка в зависимости от выделенной инфраструктуры (IaaS).

**Из обсуждения на встрече:**

> «Итог: нагрузкам нужна формализованная характеристика этих trade-off и динамическая настройка в зависимости от выделенной инфраструктуры (IaaS), а не фиксированный выбор разработчиком приложения» — Server - CMS _ Composable Memory System - workstream, 2026-09-25 — youtube.com/watch?v=UFU4ExnzhfM

## Considered Options

* Фиксированный выбор в приложении
* Формализация trade-off + динамика на уровне инфраструктуры

## Decision Outcome

Принято направление: формализованная характеристика + динамическая настройка, не фикс в коде.

### Consequences

Требует метрик стоимости пересчёта vs ёмкости — кандидат в white paper.

## Pros and Cons of the Options

### Фиксированный выбор в приложении
* просто сегодня
* не масштабируется на IaaS
### Формализация trade-off + динамика на уровне инфраструктуры
* принято
* нужен API описания trade-off
