# Малые сообщения в спеке, большие в профилях

## Context and Problem Statement

Граница «spec vs profile» для сообщений: message-пакет — низкополосный обмен с гарантированной выделенной полосой. Увеличивать message-пакет в не-кредитованных типах не стоит (риск переполнения FIFO на RX); высокополосные сообщения выносятся в профиль — там они кредитуются. Итог: short message — non-credited (гарантированная полоса, удобен как padding и телеметрия), длинные сообщения (firmware download, MCTP ~64+ байта) — через credited-механизм профилей.


**Из обсуждения в чате:**

> «Итог: short message — non-credited, длинные сообщения — через credited-механизм; в документ добавят соответствующую заметку — youtube.com/watch?v=0nYUpyDnTQk» — Ведущий Link Layer, 2026-05-07

## Considered Options

* Short non-credited + credited профили
* Один большой credited канал

## Decision Outcome

Сообщения разделены: малые в базовой спеке (non-credited), большие — через профили с кредитами.

### Consequences

Кредитование для ныне не-кредитованных типов не вводится; управление потоком — лимитами на число пакетов в LLP.

## Pros and Cons of the Options

### Short non-credited + credited профили

* выбрано: гарантия полосы для мелких, эффективность для крупных

### Один большой credited канал

* отклонено: теряется гарантированная полоса system management
* Сообщения разделены: малые в базовой спеке (non-credited), большие — через профили с кредитами.
* Кредитование для ныне не-кредитованных типов не вводится; управление потоком — лимитами на число пакетов в LLP.
