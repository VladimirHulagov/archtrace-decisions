## Контекст

Пробел данных: profiling смотрит на железо как на чёрный ящик, AstroSim/Chakra не видят внутренностей compute node (число чиплетов, HBM vs LPDDR, полоса GPU-память не экспонируется API Nvidia). Согласованный процесс: начальная простая архитектура (маппинг compute engines и памяти по бенчмарку Genome) → моделирование в AstroSim с разными коэффициентами ускорения движков → производительность + оценка memory traffic и паттернов коммуникации → уточнение дизайна → повторная детальная оценка. Обратная формулировка цели: какое максимальное ускорение движка может поддержать остальная коллекция чиплетов («чиплет в 10 раз быстрее бесполезен, память даёт только 5×» — готовая цель для RTL). Эксперимент с перепрограммируемой SDN-сетью для наблюдения реальных коммуникаций — попробовать к следующей встрече.


**Из обсуждения в чате:**

> «Зафиксировать начальную архитектуру («воткнуть палку в землю») — размер compute engine, типы памяти, типы интерфейсов — промоделировать, посмотреть паттерны и итеративно улучшать — youtube.com/watch?v=dlyb5Si18vY» — George + David, Modularity for HPC & AI, 2026-06-23


## Опции

### Option A: Стартовая архитектура + итерации

«воткнуть палку в землю», моделировать в AstroSim, уточнять

### Option B: Ждать полных данных о трафике

отклонено: внутринодовой traffic недоступен инструментам, блокирует работу на годы

## Решение

Итеративная методология: фиксация начальной архитектуры → моделирование → уточнение; пробел детальной переоценки вынести на отдельную встречу; DRAM-детали — во вторую paper.

## Последствия

Дублирование с AI HW/SW co-design (AstroSim/Chakra) признано дополняющим, не заменяющим; результаты LLM от коллабораторов (Llama/DeepSeek: полезны «длинные», не квадратные массивы) вошли в paper.
