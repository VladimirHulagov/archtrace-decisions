# JTAG поверх Flexi: без новых пинов, через reset-последовательность

## Context and Problem Statement

Требование группы: JTAG-over-Flexi без добавления новых пинов/проводов и без обязательных отдельных тестовых выводов; лучше определить обязательную последовательность действий для согласования. Секция про JTAG в спеке: вставляется дополнительный flip-flop в язык BSDL. Главный спор: можно ли войти в JTAG/boundary scan при удерживаемом reset (без «настоящего» Flexi-команды) — консенсус не достигнут.

## Considered Options

* Отдельные тестовые пины
* Переиспользовать Flexi-линии + reset-последовательность
* Virtual wire interface

## Decision Outcome

Принято: без новых пинов, через согласованную последовательность; спор reset-входа отложен (вероятно «ситуация 1.01» — построить и посмотреть).

### Consequences

Никто не реализует JTAG одинаково — спека не может зафиксировать всю детализацию; нужен пилот, который «пройдёт все шаги».

## Pros and Cons of the Options

### Отдельные тестовые пины
* простой доступ
* дорогие пины — отвергнуто
### Переиспользовать Flexi-линии + reset-последовательность
* принято: бесплатный доступ
* сложность согласования состояний
### Virtual wire interface
* транспорт уже есть
* нужен клок ~20× TCK, мин. 35 бит — отклонено
