# Иерархия — физическая (для замены), а не шинная топология

## Context and Problem Statement

Сквозная дискуссия: иерархия в дампе нужна для физического troubleshooting и замены компонентов, а не для определения внутренней шинной топологии. Тег location и физическая идентификация — отдельная проработка.

**Из обсуждения на встрече:**

> «Итог — заметка для документации: иерархия нужна для физического troubleshooting и замены компонентов, а не для определения внутренней шинной топологии» — HM - DDD _ Datacenter Diagnostics and Debug - workstream, 2026-06-18 — youtube.com/watch?v=Y4R-dapN8uY

## Considered Options

* Иерархия по шинной топологии
* Иерархия по физической заменяемости

## Decision Outcome

Принято: физическая иерархия; шинная топология — вне схемы дампа.

### Consequences

location-тег требует однозначной схемы именования слотов/координат.

## Pros and Cons of the Options

### Иерархия по шинной топологии
* точная картина связей
* бесполезна для замены — отвергнуто
### Иерархия по физической заменяемости
* принято: прямой ответ технику
* не отражает логические связи
